## 4. Mounting

Mounting was first attempted with FTK Imager via *File > Image Mounting*, selecting `LoneWolf.E01`. When KAPE was subsequently run against the resulting mount, KAPE produced warnings indicating the mount was not suitable. Rather than continue against a questioned mount, the image was unmounted and remounted with Arsenal Image Mounter.

In Arsenal Image Mounter, *File > Mount Disk Image File* was selected with `LoneWolf.E01` as the source, with the device type set to **Disk device, read only**. Read-only mode prevents any write operations from altering the evidence. The image mounted as `Local Disk (G:)`, exposing the full contents for examination.

## 5. Triage with KAPE

KAPE was run against the `G:\` mount with Targets and Modules selected to collect Windows user-activity artifacts and run reporting programs against them. Targets collected the underlying artifacts (registry hives, log files, browser data, recent file lists). Modules ran parsers against the collected Targets to produce CSV and text output suitable for review.

Items of investigative interest were identified by traversing the collected output:

- `Users\jcloudy\AppData\Roaming\Microsoft\Windows\Recent` — recently-accessed file list for the `jcloudy` user
- `Users\jcloudy\AppData\Local\Google\Chrome\User Data\Default` — Chrome browser data for the `jcloudy` user

## 6. Timeline Reconstruction with Plaso

A super-timeline was generated from the mounted image using Plaso. The intended workflow used a Docker image of `log2timeline/plaso`, but after extended troubleshooting Docker could not be made to work reliably on the examiner's machine. Plaso was instead installed natively from its GitHub source. The native install was verified by executing `log2timeline` and confirming the binary responded.

`log2timeline` was run against the mounted image to produce a Plaso storage file. `psort` was then used to render the storage file as a CSV. The CSV was opened in Eric Zimmerman's Timeline Explorer for review and filtering.

## 9. Why This Matters

Each artifact type taken in isolation is unremarkable. USB flash drive history, cloud storage installations, and even searches about ammunition or extradition are common on a typical machine and are not in themselves indicators of wrongdoing.

The conclusion drawn in this examination rests on the *combination* of artifacts: a cluster of documents authored or handled together over a roughly four-day window (`The Cloudy Manifesto.docx`, `Planning.docx`, `Cloudy thoughts (4apr).docx`, `AIRPORT INFORMATION.docx`); supporting reference material including PDFs and saved articles oriented around firearms, self-defense law, and the Second Amendment; image files such as `DeathToll.jpg`; browser searches consistent with planning travel to non-extradition countries and acquiring ammunition; references to Washington D.C., the Democratic National Committee headquarters, and "gun free zones"; and registry evidence that the same workflow involved a removable USB volume.

Considered together, and in the context of the case as briefed by the requesting party, these artifacts provide reasonable grounds for further investigation. A determination of intent or criminal liability is outside the scope of this examination and would require additional sources of evidence beyond the disk image.
